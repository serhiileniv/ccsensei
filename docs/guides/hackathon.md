# Hackathon checklist

The flow: `/ccs:brief` → `/ccs:spec` → `/ccs:implement` → (freeze) `/ccs:demo` → `/ccs:pitch` → `/ccs:deck`.
This is what the skills don't do for you.

## Hour 0
- [ ] Rubric, deadline (with timezone), submission items written down.
- [ ] Freeze time in the calendar with an alarm.
- [ ] Anti-drift lines from `hackathon/plan.md` pasted into `CLAUDE.md`.

## During
- [ ] "Can we demo now?" every ~4 h. No → that's the only task.
- [ ] Deployed link working by 25% of the time.
- [ ] Replay mode and reset built before features that depend on them.
- [ ] At freeze: stop features. Really.

## Submission
- [ ] Draft submitted 2 h before the deadline; edit after.
- [ ] Video ≤ 90% of the limit; plays without login; public or unlisted.
- [ ] Repo public (if required), README with live link, video and screenshots.
- [ ] No commits after the deadline (judges check timestamps). Fixes go to a branch.
- [ ] Every sponsor prize applied for has its own section in the submission.

## Live pitch
- [ ] Backup video on the desktop and on a USB stick; switch within 5 s.
- [ ] Do Not Disturb on, notifications off, extra tabs closed, battery full, adapter in pocket.
- [ ] Demo inputs in a snippets file; type nothing new live.
- [ ] Production build, seeded data, reset pressed before going on.
- [ ] Phone hotspot ready; replay mode one env flag away.
- [ ] One run-through on the venue screen or projector.

## After
- [ ] Run `/ccs:learn` on this event's reports.
